# Locker handoff workflow consolidation baseline



For pickup-to-donning and removal-to-deposit, reference the original authored action source for proportions and the actual runtime boundary frame for registration. Upscaling a tiny runtime frame supplies no new identity detail. Preserve gloves, helmet opening and hand contact. Review the penultimate-to-boundary pose at game resolution: copying the exact boundary frame guarantees pixel equality only at that frame, not a smooth approach. Reject abrupt prop-height or body-proportion changes before expanding the sequence to other actors. Keep candidate packs outside runtime selection until their joins and interruption semantics are verified.

For adjacent-action review, use the actual per-frame durations and a shared pivot, seek just before the boundary, and stop at the final pose. Include any deliberate worn-pose dwell explicitly; do not wrap removal back to pickup and mistake that fabricated loop for an interaction defect. The maintained example is `character/crew-underwater-v1/build_locker_review.py` with `revisions/locker-review.html`. Its source hashes and byte-equal endpoint check are technical evidence; playback loading alone is not visual acceptance.

Use actor-specific source calibration when expanding pickup coverage: the current Bill, Veld and Branforth source strips have different crown-to-boot distances despite equal output canvases. Store each source's measured foot anchors and one consistent per-actor scale in the builder. Do not reuse Bill's source measurements for another actor or normalize each pose independently. A candidate can expand review coverage without being selected by the runtime; keep those two statuses explicit.

When reusing pickup poses for deposit, record the exact source order and hashes, author deposit durations separately, and place the release marker at the first empty-handed pose. The current candidate builder is `character/crew-underwater-v1/build_deposit_revision.py`. Validate removal/deposit boundary pixels, but also verify the world-side helmet persists on the shelf after release; disappearance from a character sprite alone is not a completed transfer. Keep review-only markers distinct from inventory events until the runtime consumes them and interruption/save tests prove their semantics.

For a linear interaction with one atomic equipment commit, prefer composing stage frame lists under the existing action key and timer when that preserves the intended semantics. The current locker builder references source images and hashes them; both NPC duration and renderer must load the composed manifest. Test every composed frame, pause/save mid-action, and cancellation during the later deposit stage. Keep the original stage packs as sources and update the main review to select the same compositions as runtime. A metadata release marker does not imply world-prop transfer is implemented.

For staged locker props, derive visibility from named manifest handoff events and the saved simulation timer, not visual frame callbacks or wall-clock time. Select events by ID rather than array order. Test just before and after grasp/release for each actor and room rotation. Existing reusable-gear behavior permits a staged spare while idle; this visual must not silently introduce finite inventory. Native hand/shelf alignment and occlusion still require separate inspection after timing tests pass.

Add native captures immediately before and after each prop handoff, not only before/after the whole action. A timer test cannot detect a shelf sprite hovering above the hands. Inspect the same station camera and ensure a supported surface is visible under a released prop. Record actor-specific silhouette or size differences that remain when a shared prop overlay is reused.

When composing adjacent actions that reuse an identical boundary image, review the combined dwell across both stages. A byte-equal join can still pause too long when both source holds play in full. Preserve source timings, record composition overrides, and recalculate event times from the final duration list. Rebuild both runtime and review consumers, then rerun handoff-boundary, cancellation and saved-action tests. Shorter holds are a timing revision, not proof that silhouette discontinuities are resolved.

For multi-stage action saves, sample each stage rather than only one early checkpoint. Include a save just after the prop handoff in the real room fixture, verify restored action pixels/timer/equipment and world-prop visibility, then complete or cancel. A saved timer matching numerically does not by itself prove that renderer and room attachments consume it consistently. Current examples are `tests/test_crew_death_save.gd` and `tests/test_airlock.gd`.
