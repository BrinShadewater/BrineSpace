## Biggest opportunities to investigate next

1. Rendering: static floor/shell command caching or reduced repeated room setup.
   Keep current layered occlusion and doorway seams; compare fixed-state images
   before accepting an optimization. Broadly lowering animation fidelity is not
   a substitute for removing redundant work.
2. Progression persistence: meta writes directly truncate the JSON and do not
   report failures. Add recoverable writes and feedback without versioning the
   prototype format. Test interrupted/malformed records and recovery.
3. Architect identity: current perks are one-time starting supplies. Playtest
   whether they create distinct placement decisions; deeper role-specific effects
   need design/balance work rather than an unmeasured blanket buff.
4. World replayability: authored biomes and two fixed cryo wards are readable but
   predictable. Seeded, validated site placement is a prospective feature, not
   part of this bug-fix pass.
5. Release confidence: test the exported package and a paid longer run. Editor
   image loaders emit export warnings; verify packaged asset inclusion rather
   than assuming an editor success proves distribution works.

## Implemented rendering improvement

Batched 28 identical floor-light band polygons into a reusable mesh per room.
Light colors and power fades remain dynamic. The mesh retains the original band
shapes and triangle order; the direct path remains available for comparison with
`--unbatched-light-pools`. Fine-grained room-setup timing was also added to the
existing opt-in draw profiler. No new work runs in the normal profiling-off path
other than the mesh draw replacing repeated polygon submission.

- Fit/25 rooms: 50.65 -> 45.26 ms mean frame (10.7% reduction).
- Close/25 rooms: 32.64 -> 28.86 ms (11.6% reduction).
- Fit draw calls: 4,338 -> 3,744; close: 2,844 -> 2,493.
- Native color/brightness/scale comparison: maximum one channel step out of 255;
  20,458 of 5,760,000 bytes differed by that rounding step. Shapes unchanged.
- Culling still produces exact pixel parity.
- An earlier floor-material command cache did not improve frame times and was
  removed. No unproven cache complexity remains.

Evidence: `output/light-mesh-profile.log`, `output/light-pool-parity.log`,
`tests/test_light_pool_batch.gd`. Native comparison image reviewed.

## Next priorities, ranked

1. **Power feedback and opening pacing.** The viable paid station's mining drone
   waited 242 of 300 seconds for power, delivered 8 Metal, and ended at zero Power.
   Show charging demand and a specific next action clearly. Then compare a second
   generator and other opening choices before tuning rates. Survival alone does
   not establish satisfying pacing.
2. **Static room rendering.** Fit still averages ~22 fps on this local fixture.
   Contents cost ~11 ms and setup ~4.8 ms (setup overlaps draw-stage totals).
   Investigate static shell/prop submission and repeated shared-view setup with
   image equivalence checks. Do not sum overlapping profiler categories.
3. **Recoverable meta saves.** Type-safe loading is now fixed, but meta writes
   still directly replace the unversioned JSON and do not surface disk failures.
   Recoverable writes and clear failure feedback would protect hard-earned unlocks.
4. **Distinct Architect decisions.** Starter caches are functional but shallow.
   Playtest role-specific placement incentives and rescue opportunities before
   adding permanent output multipliers.
5. **Replayability and release discipline.** Seeded validated sites would address
   fixed-map predictability. Independently, trim production packaging to runtime
   assets and retain exported gameplay tests; editor success is insufficient.
